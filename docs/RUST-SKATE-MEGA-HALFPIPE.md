# Modular MEGA halfpipe contract

`mega-halfpipe` is one atomic kit, kind **11**, marked item **0x534B500C**, exact name `Skate MEGA Halfpipe` (stock carrier/skin/quantity unchanged). IDs 0–7, their native parts and saved layouts are unchanged; IDs 8/9 are the mini/L quarterpipes and ID 10 is the half-wall kicker. The server/shared catalogue and client 0.18.6 implementation are merged. Source 0.3.27 adds the server collision replacement described below; native riding acceptance remains open.

## Configuration and modules

Metres; anchor +X right, +Y up, +Z along travel, yaw rotates +Z toward +X. The anchor is the flat-bottom plane at X0/Z0; visual centre X4.5/Z0. Parameters in `SkateMegaHalfpipe`: width12 (four 3m lanes centred X0/3/6/9), bottom12 (Z−6…6), two quarter-circle transitions R=3/(2 sin9°)=9.588679832m, deck3 each. Total length37.177359664m; nominal rise9.588679832m. These are authored design parameters, not owner measurements. No L-module three-cell restriction applies.

All rows share X centres. Wall local long Z rotates to width: yaw270 back /90 front. Transition vertices are `(Z,Y)=(±(6+R sinθ), R(1−cosθ))`, θ=0/18/36/54/72/90°. Adjacent native chord endpoints and lane edges coincide mathematically; actual skin thickness/contact is not proved. The five modules are assembled in one transaction; independent moving, resizing or partial kits are unsupported.

## Server lifetime

Native rotation steps are retained, and explicit admin Y is a support-search hint. Admin `skate.items mega-halfpipe`, `skate.piece mega-halfpipe` and typed placement are setup/fallbacks; the normal client route must use owned item identity. Default gesture order stays unchanged; a configured unique order may include the new name. The 25m limit is eye-to-anchor, not eye-to-every-part.

Every native part retains prefab/grade bounds validation, privilege/build hooks, proximity, dry terrain/water and deploy-volume/entity occupancy checks. Per-part queries apply the same exact identity exclusions before native deploy flags/entity filtering and repeat after spawn and payment callbacks. Unsupported special-volume rules retain their native check and refuse on rejection; missing APIs fail closed. MEGA additionally checks a whole oriented envelope X−2.15…11.15, Z±(6+R+3.65), Y0…R+0.05+3 for permission and world/construction/deployed/player obstructions, before spawn, before registration and after payment callbacks immediately before commit. Only the exact placing player, verified selected support/carrier and current transaction members are excluded. Existing MEGA metadata reserves this envelope against later park placements, including partial groups; arbitrary vanilla construction and future moving obstructions are not prevented by this reservation. Air above the extra3m remains outside it.

The existing transaction owns all80 native members: complete registration precedes one verified original item debit1→0 and `Paid`; pre-debit refusal retains it. Post-debit rollback refunds only after verified complete cleanup and safe metadata. No external wall is a member. Hammer removal claims recovery before destruction and returns one item only for complete paid groups after all members/metadata are gone. Partial/free/uncertain groups mint none; interrupted states require private recovery.

Version1 metadata stores canonical kind, anchor, indexed native identities/poses and payment state under existing world/checksum, group/file-size guards. Reload reconciles actual native members; it never fills missing modules or automatically mints an item. A partial group retains its reservation until removed. Older source cannot read the new kind: keep matching private world/metadata/source backups. Release pins and live installations are unchanged.

## Server collision surface

Source 0.3.27 extends the existing quarterpipe collision lifecycle to a complete, verified MEGA group. Its Construction-layer surface uses the same 124 shared riding-profile samples at X−1.5…10.5, partitioned into 64 patches. Each patch is parented to its own native floor so entity queries, projectiles, hammer hits and upgrades retain that floor's identity. Their union has closed outer sides, ends and underside, with outward-facing triangles; internal floor and lane boundaries have no vertical faces. Sides above the riding profile remain open. The vertical datum is the first flat floor's local `bounds.max.y`, matching the client's `Origin` before `RideLift`; tilted metal chord bounds are not a datum.

Only the group's 64 verified floor members have their original physical colliders replaced. All 80 members must still match their saved native identities, owner, prefab and pose, original grade, zero skin and unit scale. Every floor must supply a physical collider. Native coping and rear guard walls remain solid. Unrelated entities, foundations, world colliders and all native antihack decisions remain active. Member positions, save metadata and the shared/client profile are unchanged.

All replacement patches become solid before the original floors are disabled. Restoration checks active and sleeping player bodies before enabling native chords. Affected bodies need verified dry, unobstructed destinations outside the whole kit, including when the kit is about to be demolished. Their actual positions are checked again before the originals are enabled and the replacement patches removed. This is a position change, never a respawn or progress reset.

When no verified exit is available, a separate Unity component owns deferred restoration, including across plugin unload. Its group marker prevents a newer plugin instance from treating its patches as native colliders or attaching a second replacement. Held members cannot be demolished, rolled back or refunded as though cleanup had finished. The owner retries only while it can verify its retained profile; an integrity failure without a verified exit is reported as incomplete restoration. No unsafe restore is claimed successful. Other parks remain available. Collision health runs independently of metadata storage failures; metadata-dependent operations remain blocked after such failures. Without readable metadata, pending markers conservatively refuse nearby changes without granting entity adoption or deletion authority. An incomplete placement held across unload requires private operator recovery; it never earns an automatic refund.

MEGA upgrades wait until players leave the complete envelope and collision restoration finishes. Rust retains its later permission, payment and upgrade checks. A rejected native upgrade requests revalidation too, so the unchanged group regains its verified riding surface.

New-placement errors still use the existing transaction rollback, with held cleanup withheld until restoration is verified. The collision surface is not an exemption from noclip. An isolated native probe passed 4,343 geometry/query checks, including the per-floor partition and copied native parent transforms. These synthetic controls do not establish actual player evacuation, complete installed lifecycle, momentum or physical-controller acceptance.

## Exact client riding contract

The client must recognize all80 members before contained small kinds, validate identity/pose/grade and clear the whole replacement on mismatch/removal/reconnect/unload. `TryMatch` supports80 with distinct-member tracking. Preview must use the same origin, yaw, module positions and envelope. The merged [SkateParks.cs](../mods/rust/client/src/SkateParks.cs) implements all twelve kinds, MEGA-first recognition, the preview and the 124-sample riding profile. [SkatePieces.cs](../mods/rust/client/src/SkatePieces.cs) supplies held-item previews. These source paths do not establish complete native placement or lifecycle acceptance.

Use `SkateMegaHalfpipe.TryProfilePoint`: **124** ordered `(forward,height)` samples, extruded X−1.5…10.5 in the anchor frame. If using `VisualOrigin` (anchor+X4.5), subtract4.5 from every mesh/coping X, giving mesh X−6…6; do not apply that centre twice. The 60 equal angular steps per transition (1.5°) include both lips and both bottom joins once; decks end at Z±(6+R+3). Heights include `RideLift=0.05`. The central bottom is Y0.05; upper decks Y=R+0.05. Apply the same transform to visual, ride mesh and normals. Analytic transition normals are `(0,cosθ,−side·sinθ)`; normals remain upward until the vertical lip. Bottom joins share a horizontal tangent; adjacent lane/module vertices must be welded with no duplicate collision lips. The lip/deck corner intentionally meets coping rather than interpolating a diagonal shortcut.

Native chords and low-wall backing are not this smooth riding surface. **Before enabling the replacement**, isolate their colliders from the mounted rider using exact owned collider/body pairs, with verified restoration on exit, mismatch and unload; never change global collision layers. Probe the required native API first. Support raycasts, spherecasts, wall and grind queries must filter these same exact backing colliders and continue to the replacement/world hit: pair collision isolation does not filter physics queries. Retain ordinary world collisions and other players. Restore only with a verified non-overlapping body pose; use a safe exit/bail pose if necessary. If pair isolation/restoration cannot be proved, leave MEGA riding unavailable; a visual replacement alone is insufficient. No fixed vertical offset guarantees clearance of thick native chords near vertical.

Coping: two cylinders/edge segments, radius0.05, axis +X from−1.5 to10.5, centres `(forward,height)=(±(6+R),R+0.05)`. Ends stay within the reserved margin. Grind/stall capture is intentional and uses actual signed travel/alignment; a backing wall is never an automatic grind. Client guards run along the rear deck edges, height1 above the deck; side exits are open and are not coping. Visual/collision/edge geometry must coincide.

Drop-in must retain the near-vertical normal and signed full tangent velocity, then apply gravity once. Current `Sense` substitutes up for normal.y≤0.3 and wall probes treat normal.y<0.5 as a wall: profile-aware support/wall handling must change before acceptance. Pump uses actual travel-relative descent/bottom timing and existing bounded energy; seams never reset/recharge it. Passive air exit preserves XYZ tangent velocity with zero pop; deliberate pop adds vertical impulse once. Landing uses the actual surface normal and whole incoming velocity with existing impact/bail limits. Uphill stall reverses physical velocity into fakie without a forced nose turn or reverse-speed penalty. Air/grind/bail clear pump state; coping leave/re-entry must not double-land or duplicate trick awards.

The merged client also contains backing-collider query filters and pairwise rider collision isolation with penetration-aware restoration. [PR #456](https://github.com/Dj-Shortcut/mw2-rust-skate-rewrite/pull/456) reports in-game previews and a local `zz mega` ride on client-created geometry, with improved slope contact. That report is separate from riding a server-placed kit. Deck drop-in and support above 72 degrees remain open.

Native acceptance remains open: rotated server placement/refusal, occupancy in empty riding air, debit/rollback/removal/reload, collider restoration, visible seams/guards/coping, then deck drop-in→pump→opposite air→landing→fakie→coping→exit with real controller input. Managed compilation, geometry/accounting checks and the reported local client ride cannot establish this complete flow.

Source 0.3.20 retains the 0.3.19 MEGA deploy filtering and mirrors MEGA command/placement feedback to `PrintWarning`. Occupancy refusals include kind, part index (or assembly), collider name and layer; reverse volume-to-volume checks explicitly identify a representative collider when no physical hit exists. Long numeric name tokens are redacted and player IDs are not added. The owner reported 31 deploy refusals on 0.3.18; that code path runs before spawning, so same-transaction parts were not demonstrated as its cause. Native collider results remain unverified until an authorized runtime test.
